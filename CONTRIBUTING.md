# Contributing

Both developers should have repository write access. Discuss product changes with the household; do not treat residents as test subjects without consent.

1. Open or choose an issue with a clear outcome and acceptance criteria.
2. Branch from latest main: feature/chore-rotation, fix/payment-status or docs/design.
3. Make focused commits; keep unrelated work separate.
4. Open a pull request targeting main. Describe changes, tests and screenshots where relevant.
5. Ask the other developer for review; resolve feedback, then squash merge when agreed.

For now, only documentation changes are in scope. No install commands exist until scaffolding is approved. Do not add secrets or real household data to the repository. If AI assists, review every diff and run relevant tests yourself. Recommended repository settings: squash merging, automatic branch deletion, and review requirements where supported by the account plan.
